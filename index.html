Elite Discoveries

A first-discovery tracker for Elite Dangerous that reads a player's journals per-commander and organizes every find into searchable categories.

Elite Dangerous writes everything a player does to local journal files, but the game itself has no screen where you can review which star systems you were the first to find. This app fills that gap: on launch it presents a list of commanders found in your journals; pick one and it reads every scan for that character, applies the game's own WasDiscovered / WasMapped flags to match in-game "Discovered by" tags, and organizes findings into categories with colour-coded headers. It runs as a true native window via Edge WebView2, completely offline: no login, no API key, and nothing ever leaves the machine.

  • Commander picker on launch lets you read one character at a time; parses 250+ journal files to build that character's discovery record
  • Discoveries tab organizes finds into colour-coded category groups — Earth-Like Worlds, Water Worlds (blue), Ammonia Worlds (green), Water + Ammonia (cyan) and Anomalies (pink) — with the chosen sort applied inside each group
  • Single-column bars show system name, feature labels, and a one-click copy button to paste into the in-game galaxy map
  • Nearest-first mode: enter your current in-game system (or any previously-visited location) and re-sorts all discoveries by light-year distance in bands
  • A Codex tab rebuilds biological, geological, and astronomical finds from journal CodexEntry events, grouped by category and sub-category with a "first logged" flag
  • Every star system includes a holographic wireframe body portrait drawn from its actual stats, with atmosphere, gravity, temperature, rings, and bio/geo signal indicators
  • Stats strip totals systems first-discovered, bodies discovered and mapped, and Earth-like / water / ammonia world counts at a glance
  • Parses 259 journals in about a second, then caches each file against its size and timestamp — since journals are append-only, a refresh only re-reads the one the game is still writing
  • Elite-style panels on a warm grey background, with a redaction mode that masks the commander name for screenshots and streaming
  • Builds to a single self-contained .exe, with a script that adds Desktop and Start-Menu shortcuts

MW5 VKB HOSAS Mapper

Maps two VKB Gladiator EVO sticks for MechWarrior 5 and MechWarrior Online, with a binding editor, live control indicator, and atomic config writes to three different game formats.

MechWarrior 5 and MechWarrior Online have no built-in dual-joystick setup UI. This app fills that gap: it detects both sticks over USB, shows which control you're moving in real time with an on-screen diagram, and lets you bind in-game actions by simply pressing a button or moving an axis. It writes three different config formats surgically — only changing the bindings you set, leaving everything else untouched — with atomic writes so a failure can never corrupt the live game file. It auto-syncs changes as you edit, and ships as a one-click installer.

  • Live device panel identifies every button and axis as you move it; hovering explains what each action does in the cockpit
  • Two-section editor: Axis and Buttons, each row showing the in-game action and keybind (click to bind, press a control)
  • Photo-based stick diagram showing the VKB grips (Standard or OTA); press a physical control and its marker lights up green
  • Auto-detects MechWarrior 5: Mercenaries, MW5: Clans, and MechWarrior Online; each has its own keybind vocabulary and config format (MW5's HOTASMappings.Remap and GameUserSettings.ini, MWO's actionmaps.xml)
  • Writes surgically: only touched bindings change, unrelated config stays put, and a backup is written each time
  • Auto-sync pushes edits to the live game files in real time
  • Per-axis invert and deadzone tuning; saved profiles; conflict warning when two identical sticks share a USB VID/PID (with the firmware fix explained)
  • Guided calibration wizard, and one-click unbind for any action
  • Installs via Install MW5 VKB Mapper.bat — creates Start Menu + Desktop shortcuts, no Python needed

Anime Tracker

A weekly airing-schedule tracker for the current anime season, shipped three ways from one codebase: browser, installable desktop app, and native Android build.

Keeping up with a season of anime means checking several streaming services and release calendars; this app collapses that into one glanceable page. It queries the AniList and Jikan (MyAnimeList) APIs for the season's schedule, converts every air time into the viewer's local timezone, and lays out each day as a row of poster cards: what airs today, what episode number it's on, and where it streams. The whole thing is a single HTML file with no build step, which is also what makes the desktop and Android wrappers practical.

  • Live season data from the AniList and Jikan APIs, laid out on a Sunday-to-Saturday strip with back/forward week navigation
  • Each show card carries poster art, air time in your timezone, season and episode number, and SUB/DUB availability tags
  • Streaming-platform filter row limited to official platforms (Crunchyroll, Netflix, Hulu, Prime Video, HIDIVE, AppleTV+), with matching badges on every card
  • Favorites list: save shows you're following and get episode-airing notifications when they go live
  • Offline cache: the app works offline after the initial season load, falling back to cached data if the network is unavailable
  • A per-day count shows how many shows air that day; the current day is highlighted on the strip
  • The entire web app is one self-contained HTML file: open it in any browser and it just runs, with no server and no install
  • Desktop edition installs Start-menu and desktop shortcuts with its own icon and opens in a standalone app window
  • Android edition is a native Gradle project that installs as a normal APK with local notifications for favorite shows

Plex Media Manager

A desktop app with a companion Android client that connects a Windows Plex host to a NAS, organizes a personal media library into Plex's exact naming conventions, and browses the result with cover art and search.

Plex only auto-fetches posters, summaries, and cast info when files follow its strict folder and naming rules, and a NAS-based setup adds its own pitfalls: Plex's background service can't even see mapped drive letters. This app manages that whole arrangement: it verifies the SMB connection to the NAS share, builds the folder tree Plex expects, and renames and relocates existing media files to match. Organizing is dry-run by default: every planned move is printed for review before anything is touched. One Python engine powers three surfaces: a windowed desktop app, an Android client, and a CLI for automation.

  • Connection check covers SMB reachability, a real write-permission test on the share, and a free-space report
  • Parses messy file names into Plex's Movie (Year) and Show - s01e01 structures; subtitle and metadata sidecar files are renamed and moved with their media
  • Dry-run by default: the organizer prints its full plan, and only --apply (or the desktop confirm) commits it
  • Uses UNC paths rather than mapped drives throughout, so the Plex service always sees the library
  • Point it at the Plex server (URL + token) and it becomes a library browser: cover art, categories, and name search across everything Plex has catalogued
  • The Android app pairs with the desktop app over home Wi-Fi by entering the address the desktop shows, with no cloud account involved
  • Packaged as a standalone Windows .exe; all settings stay local in config.json
